# Etap UI i kandydat wydania — 27.10.2026

Punkt wyjścia: `f95f29d` na `codex/v3.0-stable` oraz zachowane niezacommitowane
zmiany modernizacji z 26.10. Kopia źródeł sprzed tego etapu jest prywatnie poza
repozytorium. Nie usuwano danych, tombstones, kopii ani istniejących zmian.

## Zmiany i uzasadnienie

- `components/` rozdzielono na `ui/`, `features/` i elementy `app/`; ekrany
  pozostają w `views/`. ESLint egzekwuje importy również dla ścieżek głębokich
  i dynamicznych. Nie dodano runtime ani globalnego store.
- App jest wejściem providera. Shell koordynuje funkcje; AppDialogs otrzymuje
  stabilne ustawienia/polecenia. Audio i feedback mają osobne hooki; GuidesView
  posiada własny stos tras. Memo obejmuje granice wykazane pomiarem.
- Stos dialogów zachowuje rodzica i jego szkic, renderuje warstwy w kolejności
  stosu i obsługuje lazy loading. Manager fokusu odtwarza inertność z bieżącej
  najwyższej warstwy, uwzględnia z-index, usunięcie rodzica i pierwotny overflow.
- Tabs mają Home/End i jawny type=button. Nie zmieniano wyglądu głównego przepływu.
- Shell odświeża preferencje również po lokalnej zmianie maskowania; patch
  korzysta z aktualnej fasady storage. Formularz timera nie zapisuje celów drugi
  raz — przekazuje je silnikowi. Klucze i schemat danych pozostają zgodne.

## Weryfikacja lokalna etapu

- 844 testy w 64 plikach; 0 skipped w unit. Nowe scenariusze: zagnieżdżone
  dialogi i usunięcie rodzica, pierwotna inertność, fokus i tabs w formularzu.
- Lint, typecheck, design:check, test granic, 5 prób desktop config, npm audit
  (0), build web, frontend desktopu i verify:builds przechodzą.
- Browser: timer/reload/zadanie, WebRTC i konflikty offline, historia 65 wpisów,
  paginacja i pełne wyszukiwanie, edycja/anulowanie na 390/320 px przechodzą.
- Dodatkowy browser sprawdza zagnieżdżone lazy dialogi, Tab/Escape/powrót fokusu,
  resize ze szkicem 37 minut i zachowaniem ID/deadline/running, audio, zmianę
  języka, niezależne zdarzenia stanu sync, offline i reconnect. Syntetyczny cache
  UID nie jest traktowany jako Auth: reconnect przywraca stan adaptera.
- PWA offline/recovery przechodzi, wraz z dźwiękami i zachowaniem danych.
- A11y: istniejące scenariusze PL, pięć motywów/desktop/telefon, dialog i 200%
  CSS zoom przechodzą; screen reader i sprzęt fizyczny pozostają osobnymi bramkami.
- Oficjalny emulator: 56 prób reguł, integracja adaptera dwóch profili / 1105
  sesji oraz świeży prywatny snapshot → migracja/restart/export/restore przeszły.
  Log prywatnego testu pozostaje poza Git i artefaktami CI.

Zrzuty przed/po i axe: ignorowane `test-artifacts/ui-architecture/`. Automatyzacja
Chromium nie potwierdza fizycznego telefonu, systemowego keyringu, OAuth ani
sleep/resume. Rust i instalatory wymagają świeżych checks GitHub dla kandydata.

## Stan usług i wydania

Pierwsze CI na `01d2c2c` odrzuciło czyste `npm ci`: brakowało metadanych
bundled `@emnapi/core` i `@emnapi/runtime` w opcjonalnym pakiecie Tailwind WASI.
Błąd odtworzono w pustym katalogu. Lockfile przeliczono bez zmiany wersji
zależności produktu; czyste `npm ci --ignore-scripts` przeszło. Nie usuwano
roboczego node_modules, danych ani żadnych kontroli. Pierwszy run nie jest
uznawany za passed; nowy commit wymaga ponowienia CI na wszystkich systemach.

Odczyt 27.10 potwierdził produkcyjne przypisanie `focusflow.ink` nadal do
`dpl_7kbjGztvYdG7HrryQyMG3boTXZMJ`. Produkcyjne reguły nadal mają hash
`4c8bd509f7ff07d72d75c9104bcb6145e54d607198024d8d99ae8b619cf901bf`; testowe
`d16c2a2209cf73e577d0433e04464736c1450f3ce308976ea1feb456fe980bab`, zgodny ze źródłem.
Świeże kopie obu rulesetów i 9 dokumentów produkcji są prywatnie poza repo,
z dostępem ograniczonym do właściciela. Produkcji nie migrowano ani nie zmieniono.
