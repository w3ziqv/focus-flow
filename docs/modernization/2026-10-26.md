## Wdrożona architektura i zgodność danych

```text
views/ + components/        prezentacja, układ, dostępne kontrolki
lib/timer.ts               lifecycle React, deadline, worker i zdarzenia urządzenia
domain/                    czyste zasady kalendarza i naliczania statystyk
lib/store.ts               wspólna operacja ukończenia, cele i kamienie milowe
lib/storage.ts             walidacja oraz kompatybilna fasada ff2/ff3 i zdarzenia
lib/desktop/runtime.ts     wybór adaptera localStorage / NativePersistence
lib/sync/                  Auth, zgody, migracje, outbox, merge i transport
lib/audioSubsystem.ts      preferencje dźwięku, pliki i orkiestracja silnika
lib/audio.ts               Web Audio, generatory oraz nagrania lokalne
design/tokens.json         jedyne autorskie źródło tokenów
design/tokens.css          wynik generatora, sprawdzany w CI
src-tauri/                 pliki, keyring/OAuth, IPC, tray i uprawnienia
```

ESLint chroni granicę `domain/` przed Reactem, UI, Firebase i adapterami.
Zastosowano małe wydzielenie reguł domenowych, bez kontenera DI i bez nowej
biblioteki globalnego stanu. React hook timera pozostaje adapterem lifecycle,
nie jest opisywany jako silnik niezależny od Reacta. Granice `lib/` są nadal
częściowo historyczne; nie przenoszono mechanicznie całego katalogu.

Normalne zakończenie i odtworzenie po uśpieniu korzystają z `FocusStore`.
Rozliczana jest data końca fazy, a liczniki dziś/tydzień pozostają względem
bieżącego dnia. Dni kalendarzowe używają lokalnych Y/M/D zamiast odstępu 24 h,
co uwzględnia zmianę czasu. Snapshot zachowuje ID; stare działające snapshoty
dostają deterministyczne ID z deadline. Ponowne wywołanie dla ID obecnego w
historii lub tombstones nie nalicza wpisu ponownie. Nie jest to gwarancja
exactly-once po awarii procesu, dla dwóch równoczesnych kart ani poza oknem
1000 widocznych rekordów. Zapis wielu kluczy localStorage nie jest transakcją.

Nie zmieniono nazw kluczy, wersji archiwum ani schematu Firestore. Opcjonalne
ID jest zgodne wstecz. Nie przepisywano starych statystyk i nie uruchamiano
migracji na profilu właściciela. Wszystkie profile testowe i sesje były sztuczne.
Wycofanie kodu nie wymaga konwersji danych. Przed przyszłą migracją należy
wyeksportować archiwum z audio oraz zachować natywny snapshot/backup; sprawdzić
odtworzenie w osobnym profilu. Rollout produkcji ma osobny dokument i wymaga
kontroli zgodności klientów, reguł i kopii — nie wykonano go w tym zadaniu.

Zachowano React 19, TypeScript 5.8, Vite 7, Tailwind 4, Vitest 4,
Firebase 12 oraz Tauri 2/Rust. Zaktualizowano zgodne wersje zależności z

| Obecne rozwiązanie / alternatywa | Ocena potrzeb i kosztu |
| --- | --- |
| React / Preact lub Svelte | Obecne hooki, audio, testy i desktop działają. Alternatywy mogą zmienić rozmiar runtime, lecz nie usuwają odtwarzania całej listy. Lokalny eksperyment z memo i stronicowaniem usuwa zmierzone wąskie gardło bez przepisywania aplikacji. Nie zmierzono przewagi innego frameworka. |
| Vite/PWA / SSR i Next | Osobisty timer korzysta z lokalnego stanu i statycznych zasobów. SSR dołożyłby wdrożenie serwera i osobne rozstrzygnięcia offline/Tauri. Nie wykazano potrzeby takiej migracji. |
| TypeScript / JS lub native TS | TS chroni granice danych i IPC. Repo faktycznie używa 5.8; wcześniejsze opisy TS7/Go i tabelę przyspieszeń oznaczono jako niezweryfikowane. Zmiana kompilatora wymaga osobnego prototypu zgodności i benchmarku. |
| localStorage + IndexedDB audio / pełne IndexedDB | Brak zapisu na tick; edycja 1000 wpisów nadal robi 3 zapisy. Transakcje IndexedDB mogłyby rozwiązać inny problem — crash/quota — ale potrzebują journalingu, eksportu i planu migracji adapterów. Nie zastąpiono persystencji na podstawie samej rekomendacji. |
| Firebase / własny backend | Obecne Auth i UID w regułach zapewniają kontrolowane granice; SDK offline nie zastępuje domenowego outbox/merge. Własny backend zwiększa zakres utrzymania Auth/API i nie ma wykazanej korzyści produktu. Wymagana jest zgodność wdrożonych reguł. |
| Tauri/Rust / Electron | Tauri wykorzystuje WebView i istniejący broker z ograniczonym IPC; Electron daje Chromium i proces Node. Wymiana wymaga ponownego audytu uprawnień, pakowania i testów OS. Nie wykonano benchmarku instalatorów, więc brak liczbowego twierdzenia o oszczędności rozmiaru/RAM. |
| Web Audio / nowa biblioteka audio | Generatory i lokalne nagrania działają offline. Pomiar obejmuje brak dźwięku, brown noise oraz rain. Nie wykazano wąskiego gardła uzasadniającego nowy silnik lub zależność. |

alternatywy i konsekwencje: [ADR-0010](../adr/0010-evidence-based-modular-modernization.md).

Aktualną dokumentację sprawdzono dla [memo](https://react.dev/reference/react/memo),

## System designu i sprawdzenie wizualne

`tokens.json` definiuje semantyczne kolory pięciu motywów, fonty, rozmiary,
promienie, czasy i easing. Generator tworzy CSS, a `theme.ts` czyta te same
wartości dla podglądów/eksportu. Skala odstępów pozostaje skalą Tailwinda;
geometria SVG tarczy jest własnością komponentu. Kontrakt warstw, stanów,
typografii i motywów opisuje [DESIGN.md](../DESIGN.md).

Zachowano papier, Fraunces/Instrument Sans, ceglany akcent i koncentryczną
tarczę. Usunięto brakujące tokeny, dekoracyjne kolorowe kafelki ustawień,
niepotrzebne cienie kontrolek i małe wersaliki etykiet. Wspólne kontrolki,
przełącznik i zamknięcie dialogu mają cele 44 px. Timer ma h1, działa zoom,
a ukryte presety nie są osiągalne Tabem. Modal i focus mode dzielą zarządzanie
fokusem/inert/Escape/powrotem do przycisku. Zamknięty focus mode nie montuje
drugiej tarczy. Lazy widoki/dialogi pokazują nazwany stan loading zamiast pustki.
Zachowano istniejące empty/error/offline i bounded chunk recovery z retry.

Przed oceną wykonano i obejrzano ekrany timera, statystyk i ustawień na
desktopie i telefonie. Po zmianie: timer 1440/768/390 px, statystyki i ustawienia
1440/390 px oraz edycja historii 390/320 px. Testy layoutu sprawdzają brak
poziomego overflow i co najmniej 128 px szerokości pola edycji. Automatyczne axe
dla 14 stanów (w tym pięć motywów w dwóch szerokościach) oraz edycji historii
390/320 px, fokus dialogu i 200% CSS zoom przechodzą bez violations.
To nie jest certyfikat WCAG, screen readera ani Safari.

Przegląd `design-taste-frontend` korzystał ze ścieżki app screens, kierunku
Editorial greeting i seed `2029456425`. Zachowano istniejącą markę jako jawny
wyjątek `palette-cream`; nie zastosowano dashboardowego sidebar/grid do jednego
timera. Inspector przed zmianą: 3 FAIL (etykiety, kolorowe icon chips, brak
tytułu), 2 WARN. Końcowy timer: **0 FAIL, 1 WARN** (`hero-void`, zaakceptowana
przestrzeń skupienia). Skan statyczny plików produkcyjnego UI w trybie app:
**0 FAIL, 56 WARN**. Pozostaje dług stylów: historyczne nazwy klas, część
transition-all, cienie/blur dialogu i monospace rzeczywistych skrótów klawiatury.
Nie oznacza to usunięcia każdej arbitralnej wartości w całym repo.

Krytyka projektowa (ocena autora, nie wynik testu): baza miała limit 6/10
przez małe etykiety i cele dotykowe. Pierwsza iteracja większych kontrolek
przesunęła dół timera poza typowy desktop fold; druga zmniejszyła tarczę do
360 px i górny odstęp do 80 px. Po obejrzeniu zrzutów: design 7,4, użyteczność
7,8, charakter 7,2, treść 7,8; całościowo około 7,5/10. Priorytetem było
czytelne następne działanie, nie wypełnienie pustej przestrzeni. Nie dodano
fikcyjnych dowodów produktu, ilustracji ani zewnętrznych zdjęć.

| Accessibility | Axe w 14 stanach i dwóch szerokościach edycji historii bez violations, klawiatura dialogu, CSS zoom 200%, layout pięciu motywów. Manualne incomplete pozostają w raporcie axe. |
| Czysta instalacja | `npm ci --dry-run` oraz rzeczywiste `npm ci --ignore-scripts --no-audit` w osobnym pustym katalogu przechodzą. Bez modyfikacji roboczego node_modules; nie jest to test skryptów instalacyjnych na innych OS. |
| npm audit | 7 pakietów z advisory (3 high, 3 moderate, 1 low) → 0 według bieżącej bazy npm. Nie jest to audyt OS/Rust/całego łańcucha dostaw. |

Ostatni zestaw unit trwał 13,19 s, bazowy 15,20 s. Zmieniono liczbę testów,
discovery i obciążenie środowiska, więc nie jest to dowód przyspieszenia testów.
Nie usunięto szerokich istniejących testów adversarial tylko z powodu częściowej
duplikacji. Koszt i flakiness wymagają historii wielu uruchomień CI; lokalne
powtórzenia nie dają statystyki niezawodności.

Test offline ma ograniczony czas oczekiwania na instalację service workera;
nieudana instalacja nie zatrzyma go bez końca na `serviceWorker.ready`.
Podczas końcowego sprawdzenia wykryto taki zawis po równoległej przebudowie
artefaktów; po ukończeniu buildów scenariusz PWA przechodzi. Pomiarów CPU
nie wykonuje się podczas budowania lub testowania.

CI korzysta z `.node-version` 24, sprawdza wygenerowane tokeny i jawnie
rozdziela unit od emulatora. Zestaw integracyjny odmawia uruchomienia bez
loopback emulatora. Native CI zachowuje swoje cargo/OS kontrole; porównanie
źródeł przy ponownym użyciu instalatora uwzględnia też Vite, HTML, public,
tsconfig i wersję Node. Artefakty browser CI obejmują zrzuty historii mobilnej
i ekran błędu. Nie uruchomiono nowych workflow zdalnie i nie tworzy się
z tego powodu dowodu zielonego CI dla bieżącego diffu.

Odtworzenie kontroli: `npm run lint`, `npm run design:check`, `npm run test:run`,
`npm run build`, `npm run build:desktop`, `npm run verify:builds`,
`npm run test:browser`, `npm run test:a11y`, `npm run test:web-offline`.
Browser wymaga Chromium/Playwright. Integracja: oficjalne Firebase
`emulators:exec --only firestore --project demo-focus-flow-security
"npm run test:rules && npm run test:integration"`. Java 21 i Node 24 wymagane.
Test migracji z prywatnego snapshotu pozostaje osobnym, świadomym krokiem;
nie pobierano danych użytkownika, aby go wykonać.

## Bezpieczeństwo usług i pozostałe ograniczenia

Potwierdzono w odczycie usług Google Auth i domeny obu projektów. Projekt
testowy ma ruleset zgodny z repo; produkcyjny `focus-flow-70527` nadal ma
starsze reguły, bez części kontraktów v3. Nie wykazano przełamania UID, ale
nie wolno utożsamiać wyniku testów repo z zabezpieczeniem wdrożenia. HTTP 200
z `focusflow.ink` nie zawiera nagłówków ochronnych obecnych w `vercel.json`.
Wyniki i hashe: [cloud-context](cloud-context-2026-10-26.json),
[audyt bezpieczeństwa](../../specs/security/SECURITY_REPORT_2026-10-26.md),
[audyt reguł](../../specs/security/FIRESTORE_AUDIT_2026-10-26.json),
[model zagrożeń](../../specs/security/Focus%20Flow-threat-model.md).
Nie zmieniono konfiguracji Firebase/Vercel ani danych produkcyjnych.

Pozostają do oddzielnej weryfikacji lub decyzji:

- Produkcyjny rollout klienta, reguł i headers, ze sprawdzoną kopią oraz
  [planem wycofania](../PRODUCTION-ROLLOUT-3.0.md).
- Świeże cargo test/Clippy/audit, instalatory Linux/Windows/macOS, keyring,
  mini-window, rzeczywiste uprawnienia i uśpienie OS. Źródła Rust bez zmian;
  lokalnie nie ma toolchainu. Stary wynik Desktop CI nie pokrywa tego diffu.
- Interaktywny OAuth dwóch kont, odwołanie tokenów, Safari/iOS, fizyczny słabszy
  telefon, odsłuch/hardware audio i test czytnikiem ekranu. Testy zegara i
  syntetyczne CPU nie zastępują tych scenariuszy.
- Crash/quota podczas wielu zapisów web, równoczesne timery w osobnych kartach,
  replay starszy niż okno historii. Nowy kod ogranicza konkretne duplikaty,
  nie wprowadza transakcyjnego dziennika.
- Import do 250 MiB może blokować słabszy sprzęt; parser w workerze/niższy limit
  wymaga pomiaru i osobnego rozwiązania. Dane lokalne i kopie pozostają plaintext.
- Zewnętrzne webhooki są blokowane przez obecny CSP. Nie osłabiono CSP i nie
  dodano proxy; nie deklaruje się powodzenia end-to-end dla dowolnego odbiorcy.
- PWA nadal precache'uje SDK Firebase; większy lazy chunk powoduje ostrzeżenie
  builda. Tylko wykonanie/startowy import jest opóźniony. Nie obiecuje się
  mniejszego całkowitego pobrania offline ani zużycia baterii.
- Czysta instalacja zgłasza deprecation `glob@11.1.0` z `workbox-build@7.4.1`.
  Npm audit obecnie nie raportuje dla niego advisory; śledzić upstream zamiast
  wymuszać niezweryfikowaną główną wersję przechodniej zależności.

Zmiany pozostają lokalne i przeglądalne w diffie. Nie wykonywano commit/push,
publikacji, deploy ani migracji realnego profilu. Zrzuty i szczegółowe logi są
lokalne, z syntetycznych profili; bez tokenów i prywatnej historii właściciela.
